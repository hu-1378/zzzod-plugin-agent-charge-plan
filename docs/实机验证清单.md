# 实机验证清单（特训目标体力计划）

这份清单用来把「只在留档截图上验证过」的东西搬到真游戏里过一遍。
每条都是：**在哪个画面 → 点什么 → 应该看到什么 → 不对时记什么**。
不需要改代码，照着做、把结果填进最后的记录模板就行。

> 带 ⚠ 的条目是**已知没验证过、最可能翻车**的地方，优先做。

---

## 0. 准备（做一次就够）

1. **环境**：Windows，游戏分辨率 1920x1080，窗口模式或全屏都行（**中途不要改分辨率**）。
   游戏语言必须是简体中文——OCR 是按中文训练和调阈值的。
2. **放插件**：插件目录放在一条龙安装目录的 `plugins/agent_charge_plan/` 下。
3. **启动一条龙**，确认应用列表里能看到「特训目标体力计划」。看不到就先别继续，
   把一条龙的启动日志发给开发者。
4. **配置先保持预览**：打开
   `config/<账号下标，两位数字>/<应用组>/agent_charge_plan.yml`，确认：

   | 键 | 第一次验证时的值 | 说明 |
   |---|---|---|
   | `dry_run` | `true` | 只出日志、不写内置体力计划。**第 9 条之前别关** |
   | `target_agent_name` | 空 | 空 = 用游戏里当前设的特训目标 |
   | `goal_mode` | `agent_stage` | 按角色养成缺口排计划 |
   | `include_drive_disc` | `false` | 驱动盘分组先不排 |

5. **日志在哪**：一条龙工作目录下的 `.log/` 文件夹，取最新的那个文件。
   需要截图时按游戏截图键，或者用一条龙自己的截图功能；调试截图会落在
   `.debug/images/`。
6. **一个方便的做法**：把日志窗口和游戏并排放着跑，边跑边看，失败点一目了然。

## 1. ⚠ 起点不同，能不能走到「快捷手册-训练」

**为什么查**：进页面的第一步是 `round_by_goto_screen('快捷手册-训练')`，它靠主仓的画面路线
一路点过去。这套路线原本是给大世界站街准备的，从副本里或战斗中起来能不能连通，没验证过。

| 场景 | 怎么造 | 期望 | 失败时记什么 |
|---|---|---|---|
| A 大世界站街 | 站在六分街街头 | 节点「前往训练TAB」成功，停在快捷手册的训练 TAB | 日志里该节点的 status 原文 |
| B 在副本结算/准备界面 | 手动打一个已经清过的本，停在结算画面再启动 | 同上；允许它先退出副本 | 卡在哪一步（日志最后一行）+ 截图 |
| C 正在战斗中 | 进战斗后立刻启动 | 要么等战斗结束再走，要么明确报失败，**不能卡死循环** | 日志的重复行、跑了几分钟 |

判定「成功」的硬标准：节点「确认特训目标页」返回成功，日志出现「读取清单」阶段的
「第 1 屏读到 N 条」。

**如果失败**：记下 ① 当前在哪个画面 ② 日志最后 20 行 ③ 重试 3 次是否都失败。

## 2. ⚠ 左侧分类「特训目标」的蓝底高亮阈值稳不稳

**为什么查**：判断「我在特训目标页」主要靠左侧分类那一格的蓝底像素比例
（代码里要求蓝色像素占比 ≥ 30%）。这个阈值只用留档截图量过，实际画质、
显示器色彩设置、HDR 开关都可能让它偏。

做法：在「快捷手册-训练」页，手动把左侧分类在各个条目之间点来点去，每次点完看日志：

| 你在哪 | 期望日志 | 不该出现 |
|---|---|---|
| 点在「特训目标」上 | 判定为在特训目标页（脚本继续往下读） | — |
| 点在别的分类（例如「作战」「材料」） | 判定为**不**在特训目标页 | 误判成在特训目标页 → 后面的读取全部错位 |

再换一次画质（设置里把画质从「高」调到「标准」）重复一遍。

**失败时记什么**：① 画质档位 ② 有没有开 HDR ③ 截图（能看到左侧那一格）
④ 日志里判定结果。如果只有某个画质下不稳，这条要写进报告——开发者需要调阈值。

## 3. 读角色名

**在哪**：特训目标页。**期望**：日志「当前特训目标 XXX」和页面顶部角色卡上的名字一致。

- 换一个带间隔号的名字（例如「安东·伊万诺夫」）再跑一次，确认间隔号没丢字符。
- 把特训目标**清空**（弹窗里点「清除目标」）再跑：期望日志是「没有设置特训目标」，
  并且**不报失败**，后续条目为空。

**失败时记什么**：页面上完整名字 + 日志里读到的名字（差在哪个字最有价值）。

## 4. ⚠ 读清单 + 滚动收集：滚动量和惯性

**为什么查**：读清单是「读一屏 → 往下拖 → 再读 → 直到没有新条目」。
拖不动会被误判成「已经到底」，拖太猛会漏条目，两个都只会在实机上暴露。

**期望的日志长相**（每屏一行）：

```
特训目标清单 第 1 屏读到 2 条，新增 2 条，累计 2 条
特训目标清单 第 2 屏读到 2 条，新增 1 条，累计 3 条
特训目标清单 第 3 屏读到 2 条，新增 1 条，累计 4 条
特训目标清单 第 4 屏读到 2 条，新增 0 条，累计 4 条
```

最后一行是「已经滚到底」。

**怎么对**：跑之前先用眼睛把游戏里的条目**数一遍、抄下来**（含分组名），跑完之后
跟日志里打印的条目逐条比对。

| 现象 | 说明 | 记什么 |
|---|---|---|
| 第 1 屏之后立刻「新增 0 条」 | 拖拽没生效（游戏没跟上），会漏掉后面所有条目 | 日志 + 游戏里实际条目数 |
| 条目数比手抄少 1~2 条 | 一屏的内容被滚过头了 | 差的是哪几条 |
| 条目数对，但分组名是空的 | 分组标题在上一屏，没读到 | 是哪几条 |
| 一直读到「第 12 屏」才停 | 滚动次数到上限 | 日志全部行 |

**调参方向**（写给开发者看的，验证时不用改）：
`read_agent_plan_list.py` 里 `SCROLL_MARGIN`（拖拽离边缘的像素）、`SCROLL_WAIT`
（滚完等多久）、以及一次拖拽的距离。漏条目就减小拖拽距离/加大等待；
误判到底就加大拖拽距离。

## 5. ⚠ 电量识别，以及识别失败时按 240 估

**在哪**：特训目标页（资源栏右上角）。**期望**：日志
「剩余电量 X 储蓄电量 Y 以太电池 Z」与游戏资源栏上的数字一致。

分三种情况各跑一次：

| 情况 | 期望 |
|---|---|
| 自然电量正常、无储蓄、无电池 | X = 游戏里电量，Y=0，Z=0 |
| 有储蓄电量 | Y 对得上 |
| 背包里有以太电池 | Z = 颗数（不是电量数） |

**⚠ 重点看这个**：如果日志打的是「电量识别失败，按自然电量上限 240 处理」，
那是**异常分支**的降级，符合设计。但如果日志显示识别「成功」而三个数全是 0，
那说明流水线读到了空结果——这种时候计划会全部排成「今天电量不够跑一次」。
碰到就记下来，开发者需要判断要不要把全 0 也当失败处理。

**失败时记什么**：游戏资源栏截图 + 日志那一行 + 有没有开储蓄/电池。

## 6. ⚠ 更换特训目标弹窗（四条一起做）

前提：配置里 `target_agent_name` 填一个**和当前不一样**的代理人名字。

### 6.1 点名字框中心上移 80px 会不会点偏

**为什么查**：弹窗每格是「头像在上、名字在下」，代码点是「名字框中心往上 80px」。
这个偏移只在截图上看过。

做法：盯住点下去的那一下。**期望**：点中的是目标代理人那一格的头像，弹窗随后关闭，
页面顶部角色名变成目标名字。

| 现象 | 说明 |
|---|---|
| 点到了隔壁格 | 偏移量或名字框坐标需要调 |
| 点到了名字上（没选中） | 说明头像比 80px 更高/更低 |
| 点到了下面一行 | 同上 |

**记什么**：目标名字、点中的是第几行第几列、屏幕截图。

### 6.2 点了代理人之后，弹窗会不会自己关掉

**为什么查**：代码假设「点一下代理人 → 弹窗自动关闭 → 回到特训目标页」。
如果游戏要再点一次「确认」，现在的实现会在「确认切换结果」节点里反复报
「弹窗还没关」，最后把弹窗关掉并**明确报失败**。

| 现象 | 结论 |
|---|---|
| 点一次后弹窗自己关，日志「特训目标已换成 XXX」 | 假设成立 |
| 日志反复「弹窗还没关」然后失败 | 需要点两下 → 这条一定要写进报告（要改 `find_and_click_agent`） |

**记什么**：日志里「确认切换结果」那几行 + 点完之后弹窗的实际状态截图。

### 6.3 已经是这个角色时，不能重复点

做法：把特训目标手动设成 A，配置里也填 A，再跑一次。

**期望**：日志「已经是目标」（或「A 已经是选中状态」），**没有**出现点击动作
（可以看鼠标有没有动）。

### 6.4 目标在列表第二屏

做法：挑一个列表靠后的代理人（例如弹窗里第二行的角色）作为目标。

**期望**：自动往下滚（最多 3 屏）然后找到并点中；日志出现「没看到 XXX，滚动第 1 次」
属于正常。

**失败时记什么**：目标名字、滚了几次、最后报的是什么。

## 7. ⚠ 恶名狩猎（深度追猎）的计划项该填什么

**为什么查**：内置体力计划里「恶名狩猎」走的是独立应用「深度追猎」。
本插件生成的计划项只填了副本名，`level` 用默认 `默认等级`、
`notorious_hunt_buff_num` 用默认 `1`。这两个默认值在深度追猎里对不对，没人验证过。

**在哪**：游戏里手动进一次「恶名狩猎 → 深度追猎」，看清两件事：

1. **等级选项**：界面上有哪些等级（默认/普通/困难/…），默认选的是哪个。
2. **buff 选项**：界面上有几个 buff 位置、默认选第几个。

**期望**：内置体力计划用「默认等级 + buff 1」能正常进本。

**记什么（这条最需要文字记录）**：
- 深度追猎界面上「等级」的全部可选项，以及默认项
- buff 的可选个数、默认值
- 用默认值跑一次，卡在哪一步（如果卡）

> 如果默认值跑不通，开发者需要让插件按配置填这两个字段——所以把选项名
> **一字不差**抄下来最有用。

## 8. ⚠ 材料缺口（两条路：材料预览栏 / 养成指南→材料计算弹窗）

材料缺口有两条读法，脚本会自己选：

- **路 A 材料预览栏**（养成方案详情页右侧）：只有图标和「已有/所需」数字，**没有材料名**，
  只能告诉你「还缺」；这条路走完照样**排不了材料计划**。
- **路 B 材料计算弹窗**（养成指南 → 养成材料计算 → 确定 → 结果页）：四列表**带材料名**，
  能对到材料表、算出次数。路 A 一行都读不到时，脚本会自动走路 B。

### 8.1 路 A：材料预览栏

**在哪**：特训目标页 →「查看攻略」进养成方案详情。**期望**：日志打印 4 行
形如「（无名字，只有图标） 已有 60 所需 159 还差 99（60/159）」。

**失败时记什么**：日志里 `材料缺口没读出来` 的原文（它不致命，会继续往下跑）。

### 8.2 路 B：从养成指南进材料计算弹窗（⚠ 全新的路，一定走一遍）

**为什么要查**：这条路是后加的：养成方案详情 →「更多方案」→ 养成指南 →
「养成材料计算」→ 弹窗 → 「确定」→ 结果页。页面路径上一环出错就整段读不到，
而且**这页只在截图里见过**。

| 步骤 | 你在画面上应该看到 | 日志/期望 |
|---|---|---|
| 1 | 养成指南页（左上角标题「养成指南」） | 节点「进养成指南」成功（不会卡在「没有下一个节点」） |
| 2 | 看到粉色横幅上的代理人名字 | 日志里读到的名字 = 页面上那个 |
| 3 | 点「养成材料计算」→ 弹出材料计算窗 | 节点「打开材料计算」成功（弹窗标题「养成材料计算」） |
| 4 | 弹窗里直接点「确定」 | 节点「点确定出结果」成功 |
| 5 | 结果页：上排图标 + 「养成材料明细」四列表 | 日志逐行打印材料名 + 已有/所需，最后给出图标概况 |
| 6 | **弹窗自己关掉，回到养成指南页** | 节点「关掉弹窗」成功，日志「明细表读到 N 行，弹窗已关」 |

**特别看四件事**：

- **代理人是不是同一个**：路 B 走的是「更多方案」进去的页面，要确认它显示的
  还是特训目标那个角色（名字对得上）。对不上说明「更多方案」记的不是当前角色，
  后面的材料数字就全错。
- **四列表的行数**：把游戏里四列表的行数数一遍，跟日志对比。截图里是 6 行
  （特化流明芯片 / 「仓鼠笼」访问器 / 异常组件 / 增强型异常组件 / 特化型异常组件 /
  音擎能源模块），实机应该也是这 6 行。
- **弹窗最后有没有关上**（第 6 步）：读完会点右上角「关闭」把弹窗收掉，读失败也会尽力关。
  如果日志出现「点『关闭』没成功」或「点了『关闭』但弹窗标题还在」，
  说明界面上弹窗还开着，下次跑之前手动关一下。
- **结果页加载慢不慢**：刚点完「确定」时结果页可能还在转圈，第一天读空会自动
  **等一秒重读一次**（日志「等一秒再读一次」）。两次都空才失败，失败原因分两种：
  「有表头但没有数据行」（页面出来了、可能要往下滚）和「结果页没出来」（确定没生效）。
  记下是哪一种，这决定后面调等待时间还是调按钮点击。

**失败时记什么**：卡在第几步、那一步的画面截图、日志最后 20 行；特别是「读明细表」
「关掉弹窗」两个节点的 status 原文。

### 8.3 配了材料目标才排（可选）

在 `agent_charge_plan.yml` 里加一段：

```yaml
material_goals:
  - material_name: 特化流明芯片
    target_floor: 100
```

**期望**：日志出现「材料目标 1 条，换算成 1 条计划条目」，并且这条计划项出现在
写入清单里（副本名是「琢光测试」这类，不是材料名）。

**没读到带名字的材料时会怎样**：日志是「材料缺口里没有带材料名的条目…跳过材料排计划」，
计划里不含材料这一档，**但不会报错**。

**⚠ 名字要写全**：`material_name` 要和页面上的材料名对得上（括号写不写都行，
但「初阶/高阶/特化」这种一个字都不能差）。写错时不会报错，只是那条目标按
「没读到已有数量」处理、先排 1 次。

## 9. 写入内置体力计划：先预览，再真写

### 9.1 预览（`dry_run: true`，默认就是这个）

跑一次，看日志：

- 每条计划一行 `[排上] 代理人-调查员记录 → 实战模拟室|基础材料|调查专项 次数 1 卡数 5 电量 100`
- 认不出的条目会有 `[注意]` 行（版本加了新条目时正常，**不该报错中断**）
- 最后一行「写入结果：预览（没写入），计划项 N 条（新增 x / 更新 y / 保持 z）」

**核对**：内置「体力计划」应用的配置里**没有任何变化**（预览不落盘）。

### 9.2 真写（把 `dry_run` 改成 `false` 再跑）

打开一条龙的「体力计划」应用设置页，**期望**：

- 多出/更新了对应的计划项，副本名、次数、卡数都对得上日志
- 你自己手工加的计划项**一条都没被动**

### 9.3 连跑两次

再跑一次，**期望**：第二条日志是「保持」而不是「新增」，
内置体力计划的条目数**不变**（这条就是 upsert 幂等）。

**失败时记什么**：把 `config/<账号>/<组>/charge_plan.yml` 跑前跑后各复制一份对比。

---

## 10. 用内置体力计划真跑一轮（最后一步）

**期望**：内置「体力计划」按新写的条目依次进本，进本前扣的体力量与计划里写的一致
（实战模拟室按卡数扣、专业挑战室 40、区域巡防/恶名狩猎 60）。

**失败时记什么**：卡在哪个本、进本前后电量、日志里该本的报错。

## 速查：日志关键字对应哪一步

| 日志里出现 | 对应步骤 |
|---|---|
| `特训目标体力计划开始` | 应用启动，打印目标模式和是否预览 |
| `前往训练TAB` / `已进入特训目标页` | 第 1、2 条 |
| `当前特训目标 XXX` | 第 3 条 |
| `特训目标清单 第 N 屏读到…` | 第 4 条 |
| `剩余电量 X 储蓄电量 Y 以太电池 Z` | 第 5 条 |
| `已经是目标` / `点击 XXX` / `弹窗还没关` | 第 6 条 |
| `材料缺口没读出来` / `（无名字，只有图标）` | 第 8.1 条（路 A） |
