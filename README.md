# 特训目标体力计划

绝区零一条龙第三方插件。

## 要解决的问题

内置的「体力计划」应用需要手工逐条配置「打哪个副本、打几次」。本插件读取游戏自带的
「快捷手册 → 训练 → 特训目标」页面，把游戏已经算好的养成缺口自动翻译成体力计划。

三种运行模式（`run_mode`）：

| 模式 | 做什么 |
|---|---|
| `plan_only` | 只算计划，写进内置体力计划的配置，由内置应用去跑 |
| `execute` | 自己边跑边算边刷，刷完自动切下一个角色 |
| `audit` | 只读核对，按角色输出清单、计划与截图，不动任何配置 |

两种目标语义：

- 按角色养成：读特训目标页的条目进度（如 `129/290`、`4/60`），没满足的条目生成计划项。
- 按材料库存：读「养成材料明细」的四列表（所需 / 已有 / 仍需获取），按缺口换算刷本次数，
  把材料数量维持在指定下限。

## 实现要点

- 纯本地识别：`ctx.ocr`（onnx）+ `ctx.tm`（模板匹配），不调用任何在线 AI 服务。
- **完全不动主仓**：内置应用代码一行不改。画面区域写在插件自己的
  `screen_info/*.yml`（画面名 `快捷手册-特训目标`，全局唯一，绕开与主仓「快捷手册」重名被跳过的问题）。
- 不改内置应用代码的另一个办法：通过 `ctx.run_context.get_config(app_id='charge_plan', ...)`
  拿到内置体力计划配置的**同一个实例**，改 `plan_list` 后 `save()`，内置应用立即生效。
- 生成的是具体副本计划项（`区域巡防/猎人与忠犬` 之类），不是「代理人方案培养」类型，
  因此不触发内置「盲选列表第一个代理人头像」的逻辑。

## 进入路径备忘

- 特训目标页：快捷手册 → 训练 TAB → 左侧「特训目标」
- 更换特训目标：特训目标页 → 角色卡右侧「更换特训目标」（**游戏同时只能设一个**）
- 养成方案详情：特训目标页 → 「查看攻略」；右侧「材料预览」直接给每种材料的 已有/所需
- 养成指南：养成方案详情 → 「更多方案」→ 角色名下方「养成材料计算」

## 状态

已实现：

- **画面建档**：6 个画面的区域定义与文档（`docs/screens/`）
- **读取层**（`operation/`）：进特训目标页、读清单（分组/条目名/电量/进度）、滚动收集、更换特训目标弹窗定位、扫描全部代理人、读材料缺口
- **数据层**（`planner/`）：条目 → 计划项映射、电量换算与预算、upsert 写入内置体力计划（幂等、支持 dry-run）
- **材料层**：`assets/material_data.yml`（122 条材料 → 副本）、缺口换算次数、`material_goals` 配置
- **三条运行链路**：`plan_only`（写配置）/ `execute`（边刷边算）/ `audit`（全角色核对）
- **设置页**（INTERFACE 独立页面）：运行模式 / 目标模式 / 指定代理人 / 只预览 / 扫描模式 / 默认次数 / 驱动盘
- **扫描与批量**：扫描游戏里全部代理人（`scan_only`）→ Web 页勾选要养的（`batch_agent_names`）→ 逐个切换特训目标读清单
- **Web 配置页**（`web/`）：双击 `启动配置页.bat` 起本地服务，不开一条龙也能改配置

## 偏离主仓约定的两处（有意为之）

| 主仓约定 | 本插件做法 | 原因 |
|---|---|---|
| 测试统一放 `zzz-od-test/` | 测试随插件放 `tests/` | `plugins/*` 被主仓 `.gitignore` 忽略，测试仓 `pythonpath` 只有 `src`，物理上 import 不到插件代码 |
| 改代码同步 `docs/develop/` | 文档放插件 `docs/` | 本插件的前提是「完全不动主仓」，见 `docs/develop/spec/agent_guidelines.md` 的文档同步要求 |

配置项（写在 `agent_charge_plan.yml`）：

| 键 | 默认 | 说明 |
|---|---|---|
| `target_agent_name` | 空 | 指定代理人；空 = 用游戏里当前设的特训目标 |
| `goal_mode` | `agent_stage` | `agent_stage` / `material_floor` / `both` |
| `dry_run` | `true` | 只预览不写入。**第一次跑完确认日志没问题再关** |
| `default_plan_times` | `1` | 算不出「缺口÷单次产出」时每条排几次 |
| `include_drive_disc` | `false` | 驱动盘分组要不要一起排（驱动盘没有数量概念） |
| `material_goals` | `[]` | 材料库存目标，形如 `[{material_name: 特化流明芯片, target_floor: 100}]` |
| `last_generated_keys` | `[]` | 上一轮生成的内容键，用来清掉缺口已填平的旧条目 |
| `scan_only` | `false` | 只扫描代理人名单、不生成计划。跑一次就把全部角色名写进 `known_agent_list` |
| `known_agent_list` | `[]` | 扫描出来的全部角色名，**不用手改**，供 Web 页勾选 |
| `batch_agent_names` | `[]` | 要批量配置的角色。非空时逐个切特训目标读清单，读完恢复原目标 |

### 扫描 → 勾选 → 批量生成

1. `scan_only: true` → 跑一次插件 → 日志打印 `扫到 N 个代理人：…`，名单存进 `known_agent_list`
2. 把 `scan_only` 改回 `false`
3. 双击 `web\启动配置页.bat` → 页面下方「要养的角色」勾选 → 保存
4. 跑插件 → 逐个角色切换并读取，全部读完把特训目标恢复成进来时那个

批量时每个角色约 10~20 秒（切换 + 读一屏 + 可能滚动），日志会打印 `批量读清单 3/10：xxx`。

**注意**：游戏只能设一个特训目标，所以批量会反复改动这个设置。中途失败可能停在某个中间角色上，跑完看一眼游戏里的特训目标对不对。

## 已知限制

这些都是**有意的取舍**，不是待修的 bug。碰到时按这里说的处理，别当成故障排查。
实机怎么验证这些行为，见 `docs/实机验证清单.md`。

### 1. 驱动盘分组不纳管（默认不生成计划项）

- **原因**：驱动盘的词条是随机的，游戏也没有「驱动盘够不够」这个数量概念，特训目标页上
  驱动盘那几条只有电量、没有进度条。也就是说「该刷几次」根本没有判断标准。
- **行为**：`include_drive_disc: false`（默认）时，驱动盘分组的条目直接跳过，
  日志里是 `[跳过] 驱动盘-XXX：驱动盘分组按配置不排`。
- **想排**：把配置改成 `true`。这时按默认次数排 1 次（算不出缺口），够不够由你自己判断。

### 2. 仓库数据有约 10 分钟延迟

- **原因**：游戏「养成材料计算」页自己写着「仓库数据计算存在10分钟左右延迟，请悉知」。
  刚刷完的材料不会立刻反映到页面和库存上。
- **行为**：**不做**「刷一次 → 立刻重读页面 → 精确判断够了没」这种闭环，那样读到的是旧值，
  会把「已经够了」判成「还差」，反复多刷。材料层的换算靠
  「已读到的已有数量 + 本轮已刷次数 × 单次产出」自己累加（`planner/material_goal.py`
  的 `estimate_owned`）。
- **要校准**：刷完等 10 分钟以上再重读一次材料页，用新数字覆盖旧值。

### 3. 版本更新后出现新条目 → 降级成 warning，不中断

- **原因**：游戏每个版本都可能加新副本、新条目，插件不认识是常态。
- **行为**：认不出的条目只在 `warnings` 里记一条
  `「XXX」在副本表里找不到（可能是新版本条目），已跳过`，
  其余条目照常生成计划。**整个流程不会因为一条认不出就失败。**
- **看到这条 warning 怎么办**：确认那个副本是不是新增的。是的话在
  `planner/plan_mapper.py` 的 `_MATERIAL_ENTRY_RULES` 里加一条直配，
  或者在 `assets/material_data.yml` 补材料映射。

### 4. `amount_per_run` 目前全是 null（单次产出未知）

- **原因**：公开资料没有稳定的「每刷一次必掉 N 个」，所以材料表
  `assets/material_data.yml` 里这个字段一律留空，**不编数字**。
- **行为**：算不出「缺口 ÷ 单次产出」时，按 `default_plan_times`（默认 1 次）排，
  并加一条提示 `「XXX」单次产出未知，先排 1 次，跑完按「已刷次数 × 单次产出」估算`。
  次数会偏保守：内置体力计划是循环跑的，一轮排 1 次，多轮把缺口补完。
- **想排准一点**：给具体材料填上 `amount_per_run`（真实值），或把
  `default_plan_times` 调大。

### 5. 材料缺口有两条读法，材料名对不上就退化成「先排 1 次」

- **路 A 材料预览栏**（养成方案详情页右侧）：只有图标和「已有/所需」，**没有材料名**，
  所以能看出「还缺多少」，但没法对到材料表、算不出刷几次。
- **路 B 材料计算弹窗**（养成指南 → 养成材料计算 → 确定 → 结果页）：四列表带材料名，
  能算次数。路 A 一行都读不到时自动走这条路。
- **名字必须对得上**：配置里的 `material_name` 和页面上的材料名要一致（括号写不写都行，
  「初阶/高阶/特化」一个字都不能差）。对不上时报错是不会报的，只会按
  「没读到已有数量」处理、先排 1 次。
